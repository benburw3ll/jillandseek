# 0006. Rules first, with AI behind one capped client later

- Status: Accepted (2026-11-26)
- Date: 2026-11-26
- Deciders: the owner
- Supersedes / Narrows: (none)

Accepted 2026-11-26 by the owner's go-ahead on the recommended option (issue #7, option A).

## Context

- The plan is a finder that is strong with AI and has an agent of its own, but lighter than a full assistant: one agent that does the looking.
- A model call costs money on every use, and it sends strangers' posts and photos to an outside service. [0003](0003-privacy.md) says nothing leaves the computer without its own decision.
- There is no code and there are no model calls today. `.gitignore` ignores `.env*`, `/secrets/` and key files, so an API key has a place outside git.
- Research recorded in issue #7: an earlier local prototype put every model call behind one client with a daily cap, and its tests used a fake client.
- Matching quality can be measured without real data, on the synthetic set (#18), so an AI idea can be judged by a number before it ships.

## Decision

1. **v1 makes no model calls.** The agent in v1 is the sweep plus the matcher: deterministic, free and testable.
2. **One capped client.** Every later model call goes through one client that counts calls, enforces a daily and a monthly cap, and logs counts only. Tests use a fake client. No code path goes around it.
3. **The API key** is the owner's. It lives on the owner's computer, outside git, and the owner sets it. The cap and the key wait on the owner's `Decide:` draft. Until then the client doesn't exist.
4. **What may be sent:** a listing's text and photos, and the missing dog's traits and photos, and only for a feature the owner has turned on. Nothing about the owner, and no contact details.
5. **The agent's later jobs, in order:**
   1. a second look that compares a dog and a listing;
   2. reading screenshots and pasted texts into listings;
   3. finding new sources, which it only proposes: the owner approves each one into the registry.
6. **Each AI feature must beat the rules on the synthetic set** (#18) before it ships.

## Consequences

- v1 costs nothing to run and can be tested end to end with no key.
- The matcher (#19) has to be good on its own. That work is not wasted: it is the baseline every AI feature must beat.
- When the first AI feature is built, the client, its caps and its fake come first, and they are reviewed as a guard.
- A contact line is stripped before anything is sent, so the client's input is built from named fields and never from a whole record.
- The agent never adds a source by itself, which keeps the check in [0002](0002-sources.md) in the owner's hands.
- AGENTS.md carries "AI with a budget" as a hard rule.

## Alternatives considered

**B. AI from day one.** A model would read every listing on every sweep. It is clever, but it costs money on each sweep, needs the owner's key before anything runs, and sends every stranger's post out.

**C. Local models only** (photo fingerprints, a small text model). No cost per call, and private. But it is heavy to install, and weaker at reading messy posts. A photo fingerprint may still come later as its own decision ([0003](0003-privacy.md)).
